# Hatebu Search の要件

公開はてなブックマークから、以前保存した記事を素早く見つけるための macOS アプリと Alfred Workflow を提供する。
覚えている語で探す操作と、曖昧な記憶を Codex との会話で絞り込む操作を、同じ保存済みデータの上で続けられるようにする。

この文書は会話で決めた目的・範囲と、利用者から見た振る舞い・確認条件をまとめる。
実装方法は [設計](design.md)、実測値と確認できていない範囲は [動作確認の記録](verification.md)、インストール方法は [README](../README.md) に記載する。
以下の確認条件は、すべて実機検証済みであるという意味ではない。

## 対象と提供する価値

はてなブックマークを使い、Mac や Alfred から保存した記事へ戻りたい人を対象にする。
短い語を入力して開くまでの操作を軽くし、タイトルを思い出せない場合にも、見つかった候補を手がかりに探し続けられることを重視する。

Alfred はアプリを閉じていても検索できる。
アプリと Alfred のためにそれぞれブックマークを取得し直す必要はなく、アプリで行った更新を両方で使える。
ここでの共有は同じ Mac 内の共有を指し、別の Mac とのデータ同期は今回の対象に含めない。

| 対象 | 範囲 |
| --- | --- |
| 環境 | macOS 14 以降。Apple Silicon / Intel。Alfred Workflow の利用には Powerpack が必要 |
| 検索データ | 登録したはてなユーザーの公開ブックマークのタイトル・URL・コメント・タグ |
| 操作する場所 | ネイティブアプリ、Alfred Workflow、共通の CLI |
| AI との会話 | ネイティブアプリ内。既存の Codex CLI のログインを使う |
| 今回含めないもの | 非公開ブックマーク、asocial-bookmark、Claude 連携、別途 API キーを設定する方式、記事本文の取得、Web 全体の検索、はてな側の編集・削除 |

## 基本の使い方

初回はアプリで、はてなユーザー名を登録して公開ブックマークを取り込む。
その後はアプリの検索欄か Alfred の `hb` から検索し、見つかった記事を開く。
更新が必要な場合も保存済みの結果を先に使い、取得の完了を待たずに操作できる。

見つからないときは、検索語や候補をアプリの会話へ渡す。
利用者が覚えている内容を送ると、Codex が同じ保存済みデータを追加検索する。
途中の候補を開きながら、条件を追加したり、停止して探し直したりできる。

## 検索と更新

| ID | 要件 | 確認条件 |
| --- | --- | --- |
| R1 | 公開ブックマークを保存する | 登録したユーザーの古い記事まで取り込み、途中で取得に失敗したら前回の保存済みデータを維持する |
| R2 | 入力のたびに検索する | 検索のたびに Enter を押さずに結果が変わる。短い日本語、全角英数字、英字の大小の違いを扱える |
| R3 | 入力中も結果を使える | 検索中に前の結果を消さない。古い検索が遅れて終了しても、新しい入力の結果を上書きしない。不完全な条件で前の結果を失わない |
| R4 | 保存済みデータを先に表示して裏で更新する | 通常検索が取得や AI を待たない。更新中も検索でき、取得成功後は現在の検索語で更新を反映する。取得失敗後も検索できる |
| R5 | 同じ Mac の保存済みデータを共有する | アプリ、Alfred、CLI が同じ検索条件と保存済みデータを使う。起動する場所ごとの再取得や全件コピーを要求しない |
| R6 | 新規追加と過去の変更を取り込む | 初回以降は差分で更新し、定期的な全件照合と手動の全件更新で編集・削除を反映する。同時に更新を開始しても書き込みが競合しない |

複数の語を含む検索とフレーズ検索に加えて、タグ・ドメイン・登録日の条件で絞り込める。
結果にはタイトル、ドメイン、登録日、コメント、タグを表示し、記事を開く・URL をコピーする操作を用意する。
候補がない場合は「見つからない」と分かる表示にし、条件を変えるか会話で続ける操作へ進める。

「高速」は、まずネットワークや AI の待ち時間を通常検索へ持ち込まないことで実現する。
入力から表示までの応答と CLI の起動時間を実データで計測し、データ件数・環境・測定方法を検証記録に残す。
すべての端末・検索語に対する応答時間の保証値は、まだ定めていない。

## 結果の選択と読みやすさ

新しい検索結果と AI の最終候補は、自動で先頭を選ばず、未選択で表示する。
未選択の状態で ↓ を押すと先頭を選び、続く ↑↓ で移動し、Enter で開く。
未選択の Enter では記事を開かない。
同じ検索語のバックグラウンド更新では、利用者が選んだ記事が残っていれば選択を保つ。

| ID | 要件 | 確認条件 |
| --- | --- | --- |
| R7 | キーボードで結果を選んで開く | 検索欄に入力位置を残したまま ↑↓・Enter を使える。選択行が画面外ならスクロールする。日本語変換中は変換操作を優先する |
| R8 | 一致した語と本文を読める | 表示中のタイトル・コメント・タグ・ドメインの一致語を強調する。全角文字や合成文字で表示位置がずれない。明るい画面・暗い画面の両方で補足文字を読める |
| R9 | サイドバーを開閉できる | 左上のボタンとキーボードから開閉でき、ボタンの説明から操作が分かる |

コメント・日付・タグを、極端に小さい文字や薄い色だけで表示しない。
小さい通常文字は背景との明暗差 4.5:1 を設計上の目安にする。
これは [WCAG の文字コントラストの基準](https://www.w3.org/TR/WCAG22/#contrast-minimum)を参考にした目標であり、アプリ全体の適合を検証済みという意味ではない。

## Alfred とアプリの受け渡し

| ID | 要件 | 確認条件 |
| --- | --- | --- |
| R10 | アプリを起動せず Alfred で検索する | アプリを終了した状態で `hb 検索語` の候補が出る。Enter で記事を開き、更新中も候補を使える |
| R11 | アプリで続きを探す | Command + Enter で検索語と選んだ候補を渡せる。候補がゼロでも会話へ進める。画面を開いただけで AI に送信しない |

Alfred では検索と記事を開く操作を中心にする。
AI の会話や認証の案内はアプリ内に置き、通常検索の利用に Codex のインストールやログインを要求しない。

## Codex との会話

| ID | 要件 | 確認条件 |
| --- | --- | --- |
| R12 | 既存のログインで会話する | 普段の Codex CLI のログインを利用でき、別途 API キーの入力を要求しない。Codex が未導入・未ログインでも通常検索は使える |
| R13 | 曖昧な条件で探し直す | 記憶している内容、期間、参考候補、違う候補を伝えられる。同じ会話で条件を追加し、保存済みデータから追加検索できる |
| R14 | 現在の状態と使ったツールを示す | 起動中・検索中・完了・停止・失敗を区別し、経過時間、ツール名、検索語、件数、実行コマンドを確認できる |
| R15 | 利用者が途中で操作できる | AI 実行中も通常検索と候補の操作ができる。停止でき、条件変更後は停止完了を待って同じ会話を再開する |
| R16 | 結果と会話を失わない | 途中候補と会話を保存し、停止や再起動後も続けられる。AI の最終候補がゼロの場合に、通常検索の候補で置き換えない |

回答全体が終わったことと、個々のツールが成功したことを分けて表示する。
最終回答を受け取っていてもツールの終了通知がなければ、その操作は「結果未確認」とする。
実際のエラーを受け取った場合に「失敗」とし、推測の進捗率や残り時間は出さない。

AI に渡すのは検索条件と必要な公開ブックマークの候補とし、保存済みデータ全件を最初に送らない。
表示する候補のタイトルと URL は保存済みデータで確認し、存在しない ID を採用しない。
記事本文を読んだように説明せず、タイトル・コメントから分かることと推測を区別する。
アプリは Codex の認証情報を複製しない。

## 配布とインストール

| ID | 要件 | 確認条件 |
| --- | --- | --- |
| R17 | アプリと Workflow を配布する | Apple Silicon / Intel 共通のアプリ ZIP と Workflow を作れる。両方に同じ CLI が入り、インストール時に開発用ツールを要求しない |
| R18 | CI で検証してから公開する | 通常の変更ではテストと成果物作成を行い、公開用のタグを送った場合だけ Release を公開する。バージョン不一致やテスト失敗時は公開しない |
| R19 | 初回導入と更新の手順を示す | アプリの配置、Workflow の追加、初回起動を止められた場合の操作、対象を限定した `xattr`、アプリの置き換え方法を README に記載する |

現在は Developer ID 署名・Apple の公証を配布の前提にしない。
未公証であることと起動手順を明記し、実際の署名・アーカイブ・チェックサムの検査結果を記録する。
公開済みのファイルは上書きせず、修正は新しいバージョンで提供する。

## 確認の進め方

検索の順序、更新失敗時の保持、AI の途中イベントと停止、選択操作は自動テストで確認する。
文字の見やすさ、日本語変換、実際の Alfred 操作、初回インストールは実機で確認する。
疑似 CLI での検証と実 Codex ログインでの検証、ローカルでの検証と GitHub 上の CI 実行を区別して記録する。

検索・同期・AI・配布の具体的な構成と、要件に対応する実装箇所は [設計](design.md) にまとめる。
